## 1. 可确认的启动入口

解出的 `AndroidManifest.xml:379` 声明桌面 MAIN / LAUNCHER Activity：

```text
kt.com.fcbox.hiveconsumer.app.business.entrance.EntranceDelegateActivity
```

清单 `:403` 声明主页：

```text
kt.com.fcbox.hiveconsumer.app.business.main.MainActivity
```

主界面采用 `singleTask`，并处理 `fcapp://fcbox.com/fclink/hiveconsumer` 外部链接。

清单中还存在：

| 类名（省略共同前缀 `kt.com.fcbox.hiveconsumer.app.business.`） | 清单行 | 判断 |
| --- | --- | --- |
| `splashad.SplashActivity` | 1305 | 开屏候选，本模块匹配 |
| `advert.GDTSplashActivity` | 555 | 开屏候选，本模块匹配 |
| `advert.XWSplashActivity` | 557 | 开屏候选，本模块匹配 |
| `advert.AdvertActivity` | 553 | 广告用途尚不明确，不默认拦截 |
| `entrance.EntranceGuideActivity` | 541 | 引导页，保留 |
| `entrance.WaitDownloadActivity` | 1303 | 下载等待页，保留 |

**清单只能证明组件已注册，不能证明启动一定按这些页面依次执行。** 当前能提出的待验证路径是：桌面入口完成初始化 → 某个开屏 Activity → MainActivity。是否真的如此，需要运行时日志确认。

## 2. 首屏图片证据

`res/values/styles.xml` 的 `LauncherStyle` 设置：

```xml
<item name="android:windowBackground">@drawable/bg_launcher</item>
```

`res/drawable/bg_launcher.xml` 是一个 layer-list：白色底层 + 居中显示的 `bg_entrance` 位图，底部偏移 96dp。因此启动图片不仅可能来自 ImageView，也可能来自窗口主题。

资源 ID：

| 资源 | ID |
| --- | --- |
| `bg_launcher` | `0x7f08022e` |
| `bg_entrance` | `0x7f0801c6` |
| `bg_entrance_logo` | `0x7f0801c7` |

`activtiy_entrance_delegate.xml` 含 `iv_logo_splash` 和更新进度控件；`activity_splash.xml` 含 `ivBg`、`iv_logo_splash` 与广告容器 `fl_container`；GDT/XW 布局也含广告容器与底部 Logo。部分图片默认是 `gone`，业务代码可能再设置为可见，不能仅凭 XML 默认状态判断实际画面。

MyHook 按资源包名和资源名称匹配，不依赖硬编码 ID。它同时 Hook `Resources.getDrawableForDensity` 和 `TypedArray.getDrawable`，覆盖普通图片读取与主题背景读取，并在启动页回调处隐藏已确认的图片控件。

这能尝试清理应用自身的画面，**不能保证清掉系统进程预先绘制的 Starting Window / Android 12+ SplashScreen，也不能消除必要初始化耗时**。系统机制见 [Android 官方文档](https://developer.android.com/develop/ui/views/launch/splash-screen)。

## 3. 加固限制

Application 是 `com.Proxy.ShellApplication`，元数据 `_app_name` 指向 `com.fcbox.hiveconsumer.HiveConsumerApplication`。

APK 包含 `libijiami_1011.so` 和 `assets/ijiami_1011.VData`。`classes.dex` 的 ZIP 条目很大，但 DEX 头声明的 class_def 仅有 **41 个**，字符串表仅 **484 项**；JADX 可见的是壳和装载辅助代码，不能据此当作完整业务源码。

`analysis/shell/sources/com/Proxy/ShellApplication.java` 显示：

- `attachBaseContext` 调用 `Helper.a(context)`、`VLibrary.attachApp()`；
- `onCreate` 调用 `VLibrary.attach(...)` 与真实 Application 的 `onCreate()`。

所以没有证据支持凭空写出 `showAd()`、`goHome()`、`isShowSplash()` 等业务方法。MyHook 使用 Android 框架层的生命周期和跳转方法，不要求在装载阶段找到加固后的业务类。

原始二进制 Manifest 的头部长度是 12 字节，常规解析路径未将它还原为文本。`inspect_apk.py` 按实际头部长度解析字符串池和 XML 节点，生成可读 `AndroidManifest.xml`；它是本次样本的分析脚本，不是通用 APK 解包器。

## 4. 模块设计

模块名 **MyHook**，包名 `dev.josh.myhook`，API 102，作用域仅 `com.fcbox.hiveconsumer`，只在主进程启用。

1. `onPackageReady` 安装框架方法 Hook。
2. 通过丰巢包名和主进程筛选确定作用范围；0.1.1 不再安装版本检查用的 `Application.attach` Hook。
3. 遍历 `Instrumentation.execStartActivity` 的 Activity 调用者重载，定位 Intent 和 requestCode 参数。
4. 仅当来源为入口、主界面或已知开屏页，目标为三个确认的 Splash 类之一，且不是带 URI/Selector 或等待返回结果的跳转时，构造到 MainActivity 的 Intent。
5. 使用 `CLEAR_TOP | SINGLE_TOP` 复用主页，保留入口本身的初始化流程；不复制广告 extras 到主页。
6. 替换已确认的启动图资源，记录实际页面流转。

API 102 使用 `XposedModule` 和 `hook(method).intercept(chain -> ...)`；入口为 `META-INF/xposed/java_init.list`，依赖为 `compileOnly`。实现对照了 [libxposed 官方 API](https://github.com/libxposed/api) 与 [入口和生命周期文档](https://libxposed.github.io/api/io/github/libxposed/api/package-summary.html)。

## 5. 仍需实机验证

- 当前版本实际是否使用这三个开屏 Activity，还是使用 `AdvertActivity` / 内嵌广告。
- 开屏是否通过 `startActivityForResult`、自定义 Instrumentation 或其他路径启动。
- 进入主界面是否依赖广告页完成的状态更新或额外参数。
- 首页返回栈是否正常，是否出现重复进入主页。
- 动态加载的图片是否经过本版覆盖的资源路径。
- 去掉图像后是否仍有入口页初始化等待；这是不同问题。

用户已反馈 0.1.0 生效，但尚无完整运行日志来确认所有启动路径。0.1.1 的编译、策略测试、签名检查已通过，本次未进行手机回归测试，也未验证其他丰巢版本。

源码、安装和日志说明见 [README](../README.md)。若日志证明广告直接嵌在入口中，需要在真实 ClassLoader 就绪后进一步定位业务方法及其回调，而不能简单把入口 `onCreate()` 置空。
